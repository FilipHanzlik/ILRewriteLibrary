3. ILLink concepts and source entry points
------------------------------------------
ILLink statically analyzes IL/metadata; it does not execute application methods
to discover reachability. Conceptually:
  inputs + roots/configuration -> marking/dependency closure -> transformations
  and sweep -> output.
Real pipeline has additional steps and ordering dependencies.

Configured substitutions can permanently change output behavior (e.g., a disabled
feature method returns false). Analysis must observe that effective result.
It is not a temporary runtime invocation followed by reverting the substitution.
Replacement dependencies must be known before sweeping.

Cecil participates throughout reading, analysis representations, mutation, and
output, not merely the final serialization call.

Useful files under src\tools\illink\src\linker:
- Linker.Steps\OutputStep.cs: assembly.Write and copy/link actions.
- Linker.Steps\SweepStep.cs: removal and reference repair.
- Linker.Steps\MarkStep.cs: large, complex reachability implementation.
- Linker\Driver.cs: command parsing and pipeline.
- Linker\TypeMapInfo.cs: hierarchy/default-interface analysis; observed hotspot.
- Linker\LinkerEventSource.cs: Microsoft-DotNET-Linker events.

Current-source investigation found Microsoft.DotNet.Cecil as a package dependency,
not the public Mono.Cecil package name:
  src\tools\illink\src\linker\Mono.Linker.csproj
Before replacing Cecil, identify the exact assembly/package/source used by installed
ILLink 10.0.12. Do not assume upstream Cecil master is equivalent.

6. Creating/replaying a response file
-------------------------------------
A .rsp is plain text holding ILLink ARGUMENTS ONLY, not the dotnet executable or
illink.dll path. @linker.rsp tells ILLink to load those arguments.

Manual capture procedure taught:
1. Open publish.binlog in local MSBuild Structured Log Viewer.
2. Navigate to the actual ILLink task under _RunILLink, not merely the expensive-
   tasks summary.
3. Copy its complete command.
4. Remove the host/tool prefix; retain every reference, feature, warning, metadata
   and symbol option.
5. Save as linker.rsp beside the project, not linker.rsp.txt.
6. Redirect -out to a dedicated replay directory (console suggestion:
   out\illink-replay).
7. Run from the original project working directory.

PowerShell command, from the relevant project's directory:
  & "C:\Program Files\dotnet\dotnet.exe" "C:\Users\t-fhanzlik\.nuget\packages\microsoft.net.illink.tasks\10.0.12\tools\net\illink.dll" '@linker.rsp'

Check $LASTEXITCODE. A full rsp path alone does not fix relative INPUT paths:
working directory still matters.
Do not clean obj/bin/NuGet inputs before replay.
ILLink output is not a complete runnable publish directory.

Potential helper investigated:
  https://github.com/vitek-karas/illinkrepro
  illinkrepro create .\publish.binlog --project TrimDemo -o .\trimdemo-repro

13. What these results support and do NOT support
------------------------------------------------
Supported provisional findings:
- GC/runtime activity, interface analysis, and monitor overhead appear in both runs.
- Cecil instruction and generic/signature representations account for substantial
  sampled allocation volume.
- Most observed Instruction allocation follows a body-getter/materialization path.
- Blazor template adds allocation compared with console, especially strings.

Not established:
- Exact Cecil-only allocated bytes.
- Which ILLink operation triggers most body materialization (ungrouped callers
  still needed).
- Source of string/LargeObject allocation.
- Exact GC pause totals, retained heap, peak memory, or causal GC attribution.
- Exact API call counts/arguments or object counts from sampled events.
- Actual lock contention or the exact lock/caching mechanism in deployed Cecil.
- Reproducibility across repeated runs, production/mobile representativeness.
- End-to-end speedup achievable by SRM or any specific optimization.

Methods and GC are not independent cost categories: methods allocate, object
lifetimes affect collections, and GC often runs elsewhere. A lower allocation
percentage is not the same fraction of elapsed-time savings.

14. Architecture research: proposed, not implemented
----------------------------------------------------
User proposals:
1. Transactional edits applied at end; concern intermediate-state calculations.
2. Lazy Cecil-like API, thread-safe edits, symbolic tokens/late offsets.

Source-backed recommendation:
  Immutable input + stable IDs + compact effective edit state + method-local
  editors + planned emission.

Separate semantic publication from physical file emission.
- Original view: input metadata.
- Current view: published edits over input.
- Editor-local view: current state plus unpublished edits.
- Commit publishes semantic state, not a DLL.
- Initially support canceling unpublished edits, not full rollback of side-effecting
  analysis/worklists/diagnostics.

ILLink evidence:
- GetMethodIL must expose optimized bodies before marking inspects dependencies.
- Substitution precedence affects constant propagation.
- Marking reaches a fixed point; deferred/new helper dependencies must be included.
- Sweep requires deletion-aware resolution and effective member enumeration.
- Annotations/cache keys require stable entity identity.
- Constructed references carry generic context beyond definition IDs.
- Custom-step interfaces expose concrete Cecil types; compatibility is not automatic.

Explicit editing scopes mean controlled ownership/visibility, not merely adding
locks around setters. Start sequential, publish as needed inside analysis, then
parallelize only genuinely independent work with defined inputs.

Cecil already defers offsets and uses symbolic instruction/member references.
Both Cecil and SRM final emitters store compact row representations.
Neither novelty claim alone supports speed.

Emitter invariants:
- Separate input handles, stable entity IDs, output tokens and physical locations.
- Group methods/fields/parameters by owner for contiguous metadata ranges.
- Account for sorted-table ordering before encoding referring rows.
- Remap fixed-width IL tokens, locals, catch types and user strings.
- Re-encode compressed signature references when sizes change.
- Handle branch widening, EH, max stack, PDBs, resources and signing explicitly.
- Collect reference/heap requests before parallel body encoding with private buffers.
- Shared SRM builders are mutable, not safely concurrently appendable.
- Stable identity does not resolve signature-change versus caller-edit conflicts.
- Bound bytes in flight; cached decoded analysis data may still be necessary.

Reachability needs a logical dependency graph, not necessarily a full editable
object graph. Queues/sets can use stable IDs and discover edges on demand, but
ILLink genuinely needs hierarchy/generic/reflection analysis structures. Do not
claim all analysis objects can disappear or continually re-decode everything.

16. Measurement workflow to continue
------------------------------------
1. Finish reading existing trace views before changing source.
2. Obtain ungrouped Instruction/get_Body callers and string allocation callers.
3. Read GCStats, keeping GC CPU versus pause versus heap size distinct.
4. Identify exact Microsoft.DotNet.Cecil binary/package/source version.
5. Run repeated uninstrumented direct ILLink invocations with fixed inputs.
6. Profile unchanged binary separately; instrumentation overhead is not baseline.
7. Add targeted counters only for unresolved questions (e.g. decoded bodies or
   repeated empty override queries), not all getters with serialized arguments.
8. Compare unchanged ILLink + baseline versus compatible modified Cecil.
9. Validate output obligations and actual loading of the intended modified build.
10. Broaden to richer and eventual team workloads before generalizing.

A simple external Stopwatch can time each direct command; check exit code and
report median/spread over 5-10 initial repetitions, increasing if variability is
large. New processes still have startup/JIT/PGO costs even with warm file cache.
Do not silently remove runtime features or change trimming actions for speed.

Universal API tracing/replay was discussed but NOT recommended as the first task:
field accesses need call-site instrumentation, collections/callbacks complicate
boundaries, logging getters can materialize data, and Cecil-only replay changes
ILLink allocation lifetimes/GC context. Sampling is not exact call counting.
